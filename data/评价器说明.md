# 独立结构评价器 metrics.py 说明（A 侧，E01 地基）

## 这是什么
`a_data/metrics.py` 实现任务书 L1026–1036 规定的**结构指标** SF / SIPR，以及 L1327 要求的
**类型 / 端点 / 角色三类错误比例**。它只读候选映射和封存参考，不信任任何方法自己报的
"结构通过"字段——这正是任务书 L1036 那句"不把算法自身的结构通过字段直接当作指标"。

不含响应指标（CTC / Ebar）：那些要等 C 侧产出 audit 记录（T04），届时在此文件追加。

## 检查清单项数不是常数（易错点）

清单项数由**目标域参考结构**决定，公式：

    项数 = 2（节点双射 + 超边双射）
         + |V_t|（每节点一项类型）
         + 3 × |E_t|（每超边：类型 + 输入集合 + 输出集合）
         + Σ_e |participants(e)|（每节点–超边关联一项角色）

所以：
- **三节点、一条三元超边 → 11 项**（任务书 L1036 的例子，乘性增长 / 线性驱动-阻力）
- **二节点、一条二元超边 → 9 项**（饱和响应，输入只有 input 一个维度）

我第一版文档把 11 当作通用值，是错的。实测 300 个训练组的分布：

| 关系类型 | 清单项数 | 任务数 |
|---|---|---|
| 线性驱动-阻力 | 11 | 130 |
| 乘性增长 | 11 | 146 |
| 饱和响应 | 9 | 24 |

下表以三节点三元情形为例（11 项）：

| 类别 | 项数 | 本文检查键 |
|---|---|---|
| 节点双射 | 1 | `node_bijection` |
| 超边双射 | 1 | `edge_bijection` |
| 每个节点的类型 | 3 | `node_type:<目标节点>` |
| 每条超边的类型 | 1 | `edge_type:<目标超边>` |
| 每条超边的输入集合 | 1 | `edge_inputs:<目标超边>` |
| 每条超边的输出集合 | 1 | `edge_outputs:<目标超边>` |
| 每个节点–超边关联的角色 | 3 | `role:<目标节点>@<目标超边>` |
| **合计** | **11** | |

## 三条必须守住的规则

1. **清单由目标域参考结构确定，分母不随候选变化，但**不是**固定 11。**
   任务书 L1034："清单由完整参考结构确定，未匹配项记失败"。两层含义：
   (a) 项数由目标结构算（见上节公式），三节点三元=11、二节点二元=9；
   (b) 对给定任务，候选少给一个映射时**分母不变**——否则漏答的方法反而 SF 更高。
   实现上按目标侧遍历、未匹配项填失败占位。selftest 第 5、6 条断言守 (b)。

2. **角色一律读 `edges[].roles`，不得用 node_id 字面比较。**
   实测事实：正式组目标域节点名是 `current/ratio/next`（语义名），源域是 `b2/b1/b4`
   （随机名）；dev 组则是 `N_t/r_s/N_next` vs `A_t/r_t/A_next`。三组三种命名，
   靠字面必错。

3. **无候选任务两项记零**（L1034），分母仍算全部任务数 N。

## 用法

```bash
python a_data/metrics.py --selftest              # 自检，任务书已知答案
python a_data/metrics.py --dataset mred          # 自评价跑 MRED（正确映射当预测）
python a_data/metrics.py --dataset mred --json-out results/mred_selfcheck.json
```

- 正确映射 → 清单 11 项、SF=1、SIPR=1
- 交换两个输入节点 → 9 项通过、SF=9/11=0.818182、SIPR=0、role_error=2（对应 L132 / L1036）

  （任务书 L341"不能遗漏或重复占用"；旧实现用 `next()` 反查会静默取第一个源节点而洗成通过）

## 响应指标与返回指标（T06，2026-11-02 补齐）

T06 原文要求「独立计算**结构、响应和返回**指标」。此前只实现了结构指标，
本次补齐另外两类。

### 响应指标（L731–788）

| 指标 | 公式 | 实现 |
|---|---|---|
| CTC 方向一致率 | 一致组合数 / (干预数 × 输出数)，方向按 `sgn_η` 三分类 | `evaluate_response()` |
| E(f,I) | `min{1, (r_s − r_t)²}`，先平方后截断 | `response_error()` |
| Ebar | 任务内逐干预 E 的平均（先对输出取平均） | 同上 |
| Rhat | 已检查干预中的**最大** E，不是平均 | 同上 |

数据来源：MRED 测试组的 `sealed/intervention_points.json`（48 组 × 100 点）。
两个域用**同一组**无量纲 u 求值；SCAR/SCAN 无函数，这两项记 N/A（L957）。

**没有完成任何干预时 CTC/Ebar 为 None、status≠ok**，不按零误差通过（L788）。

### 返回指标（L1039–1047）

| 指标 | 定义 | 分母为空时 |
|---|---|---|
| VRR | 正任务中返回**且通过独立有效性检查**的比例 | None（N/A） |
| FAR | 负任务中返回映射的比例 | None（N/A） |
| Coverage | 全部任务中返回映射的比例 | None（N/A） |

正任务返回错误映射只降低 VRR，**不计入 FAR 分子**。
分母为空一律记 None，不写 0——0 会被读成"表现完美"。

### 自评价实测（封存正确映射当预测）

| 数据集 | 任务 | SF | SIPR | VRR | FAR | Coverage | CTC | Ebar |
|---|---|---|---|---|---|---|---|---|
| MRED | 660（330 正/330 负） | 0.5 | 0.5 | 1.0 | 0.0 | 0.5 | 1.0 | 0.0 |
| SCAR | 378（全正） | 1.0 | 1.0 | 1.0 | N/A | 1.0 | N/A | N/A |
| SCAN | 65（全正） | 1.0 | 1.0 | 1.0 | N/A | 1.0 | N/A | N/A |

MRED 的 SF/SIPR=0.5 是**正确口径**：L1034 规定「无候选任务两项记零」，
自评价里负任务不返回映射（正确行为），故记 0；正任务全部 1.0。

### 验收数字（可复现）

- 响应误差三行表：`(0.20,0.20)→0`、`(0.44,0.20)→0.0576`、`(-0.01,0.01)→0.0004`
- 平方反例在 dev 组：**CTC=1.0（方向全对）、Rhat=0.0576（幅度超容差 0.05）**

- Rhat 多点区分：误差 0.001/0.002/0.08 → 均值 0.0277、最大 0.08

## 尚未覆盖（诚实标注）
- **SCAR / SCAN 的响应与返回指标恒为 N/A**：它们没有响应函数、也没有负任务，
  这两类指标在这两个数据集上没有定义（不是没做）。
- **别人的方法还没有**：B 的 TopoAdv/NGM、C 的 LLM 基线、SME 都没产出原始候选，
  所以现在只有自评价（正确映射当预测），还没有方法对比数字。
- **CTC/Ebar 目前只在 MRED 的 48 个测试组上算**：其他组没有封存干预点（L1024
  只要求测试任务预生成 100 个点）。
